# Общая картина: экзамен, стенд, материалы

## Что за экзамен

- Специальность: **09.02.06 «Сетевое и системное администрирование»**.
- Формат: государственная итоговая аттестация в виде **демонстрационного экзамена профильного уровня (ДЭ ПУ)**.
- Стенд: **ГАПОУ ПК № 8 им. И. Ф. Павлова** (Москва, `pk8.mskobr`), виртуальные машины на базе VMware / ESXi, с 2025 года также авторазвёртывание на PVE.
- Комплект оценочной документации (КОД) 2026: [`01-normative/kod-09.02.06-1-2026-tom1.pdf`](01-normative/kod-09.02.06-1-2026-tom1.pdf). Критерии и порядок оценивания — [`01-normative/grading-system-2026.pdf`](01-normative/grading-system-2026.pdf).
- Форма отчётности: отдельный текстовый документ на каждый пункт, требующий отчёта; итоговый файл называется `ФамилияУчастникаМодульN`. Шаблон — [`01-normative/report-sample-2026.odt`](01-normative/report-sample-2026.odt).

## Состав экзамена

| Модуль | Название | Что проверяется | Ориентиры по разборам* |
| :-- | :-- | :-- | :-- |
| 1 | Настройка сетевой инфраструктуры | имена устройств, IPv4-адресация и VLSM, коммутация и VLAN, маршрутизация (OSPF/BGP), туннели, NAT, DHCP, DNS, NTP, локальные учётные записи, SSH | ~1 час, 25–27 баллов |
| 2 | Организация сетевого администрирования ОС | Samba AD DC и ввод клиента в домен, RAID, файловые сервисы (NFS), служба времени, Ansible, Docker, веб-сервисы, проброс портов | ~1,5 часа, 24 балла |
| 3 | Эксплуатация объектов сетевой инфраструктуры | VPN, межсетевой экран, мониторинг (Zabbix), централизованные логи, печать, резервное копирование | ~1,5 часа, 24 балла |
| 4 | Вариативная часть | задания по выбору / по условиям площадки | зависит от варианта |

\* Время и баллы взяты из конспектов [`02-modules`](02-modules/README.md) и могут отличаться от текущего КОД — сверяйтесь с нормативными документами и с заданием своей площадки.

Модуль 1 в материалах этого репозитория разобран по пунктам **1–11** (`03-walkthrough/module-1.md`), модуль 2 — по заданиям **1–4** (Samba AD, RAID, NFS, Chrony). Остальные задания модуля 2 и весь модуль 3 разобраны в сжатом виде в [`02-modules`](02-modules/README.md).

## Стенд 2026: машины и параметры

Из пошагового разбора модуля 1 (`03-walkthrough/module-1.md`):

| Устройство | Роль |
| :-- | :-- |
| `ISP` | «провайдер»: внешний интерфейс по DHCP, адресация в сторону HQ и BR (172.16.1.0/28, 172.16.2.0/28), NAT, BGP/DNS/NTP при необходимости |
| `HQ-RTR` | маршрутизатор офиса HQ: шлюз по умолчанию для HQ, DHCP для HQ-CLI, NAT, туннель и динамическая маршрутизация |
| `BR-RTR` | маршрутизатор офиса BR: шлюз для BR-SRV, NAT, туннель и динамическая маршрутизация |
| `HQ-SRV` | сервер HQ: DNS, файловые сервисы, RAID, NTP и прочие службы |
| `BR-SRV` | сервер BR: контроллер домена Samba AD и сервисы офиса BR |
| `HQ-CLI` | рабочая станция: DHCP-клиент, ввод в домен, доступ к сетевым ресурсам |

Ключевые параметры задания 2026 года (по тем же материалам):

- домен `au-team.irpo`, DNS-суффикс `au-team.irpo`;
- VLAN 100 — HQ-SRV, VLAN 200 — HQ-CLI, VLAN 999 — управление;
- SSH на серверах — порт **2026**, только для `sshuser`, `MaxAuthTries 2`, баннер «Authorized access only»;
- туннель между HQ-RTR и BR-RTR — GRE или IP-in-IP, поверх него динамическая маршрутизация (OSPF) с парольной защитой;
- NAT на ISP для HQ-RTR и BR-RTR, NAT на HQ-RTR/BR-RTR для локальных сетей;
- DHCP на HQ-RTR для HQ-CLI, DNS — на HQ-SRV.

⚠️ В текущей сборке стенда **нет виртуального коммутатора**, поэтому пункт про коммутацию VLAN (задание 4 модуля 1) в пошаговом разборе помечен как невыполняемый. В 2025 году для этой задачи использовались openvswitch / VLAN-интерфейсы на маршрутизаторе — см. архив [`2025`](../archive/2025/README.md) и справочник [`04-services/07-switching-config.md`](04-services/07-switching-config.md).

## Полезные привычки на экзамене

1. Сначала прочитать весь модуль целиком и выписать параметры (имена, адреса, VLAN, порты) в черновик-таблицу — потом настраивать.
2. После каждого пункта — проверка (`ping`, `ip a`, `show …`, `systemctl status`) и скриншот в отчёт. Скриншот должен быть кадрирован так, чтобы информация была читаемой.
3. Не забывать про сохранение конфигураций (`wr` на EcoRouter, `systemctl enable <служба>`, сохранение правил iptables и т. п.): проверяющий может перезагрузить устройство.
4. Отчёт формируется по ходу работы, а не в конце: имя файла — `ФамилияУчастникаМодульN`.
