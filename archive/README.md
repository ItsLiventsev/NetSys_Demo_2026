## Принцип: архив «как есть»

Содержимое каталогов `2022/`…`2025/` **не редактируется**. Внутри — ровно те файлы и та структура, что были в исходных репозиториях: те же `README.md`, те же относительные ссылки на картинки (`screens/…`), те же опечатки. Это сделано специально:

- архив остаётся проверяемым — можно сравнить с исходным репозиторием;
- относительные ссылки внутри архивных README продолжают работать;
- при необходимости легко обновить архив повторным импортом.

Поэтому:

- не переименовывайте и не «причёсывайте» файлы внутри `2022/`…`2025/`;
- актуальные материалы и их структура живут только в [`../docs`](../docs/README.md).

## Чем полезен каждый год

### 2022 — «классический» вариант с Windows Server

Самый старый и самый «полный» по охвату сервисов разбор: виртуальные машины и коммутация, сетевая связность (GRE, IPsec, ACL, NAT), DNS двух уровней, NTP, SMB + RAID1, центр сертификации ADCS, веб-приложение в Docker за nginx с TLS и балансировкой. Стенд: Debian 11, Windows Server 2019, Cisco CSR1000v.

Дополнительно в репозитории была инженерная обвязка:

- `azure/autodeploy/` — Terraform для развёртывания всего стенда в Azure (`ISP.tf`, `RTR-L.tf`, `RTR-R.tf`, `SRV.tf`, `WEB-L.tf`, `WEB-R.tf`, `network.tf`, `output.tf`);
- `docs/autodeploy/`, `docs/autoassess/` — Terraform + PowerCLI для автоматического развёртывания в vSphere/NSX-T/VCSA и оценки;
- `docs/autochecker/` — PowerShell/YAML-авточекер конфигураций (`main.ps1`, `CLI.ps1`, `SRV.ps1`, `ISP.yaml`, `WEBL.yaml`, `WEBR.yaml`);
- `docs/marks/` — таблицы оценок `demoassess.xlsx`, `demoassessauto.xlsx`.

## История коммитов исходных репозиториев

Импорт выполнен не «копированием файлов», а слиянием деревьев: у каждого каталога есть коммит-импорт с **двумя родителями** — текущая ветка и ветка исходного репозитория. Поэтому вся история сохранена и достижима.

Для года `YYYY` исходная история смотрится так:

```bash
# коммит-импорт этого года (см. MANIFEST.md)
git show <import-sha> --stat
# история исходного репозитория целиком
git log --oneline <import-sha>^2
# файл так, как он лежал в исходном репозитории
git show <import-sha>^2:README.md
```

Просмотр содержимого по путям внутри `archive/` покажет только коммит импорта — это ограничение любого subtree-подобного переноса: пути в старой истории были в корне, а не в `archive/YYYY/`.

## Что делать с исходными репозиториями

После публикации этого архива исходные `NetSys_Demo_2022`…`NetSys_Demo_2025` больше не нужны как отдельные репозитории: их содержимое и история полностью продублированы здесь.

Рекомендуемый порядок:

1. Убедиться, что архив в `main` этого репозитория содержит всё нужное (см. `MANIFEST.md`: число файлов и объём совпадают с исходниками).
2. Вместо безвозвратного удаления — **архивировать** репозиторий на GitHub: `Settings → Archive this repository`. Он станет read-only, останется доступным по прежним ссылкам, а форки и клоны не «умрут» с ошибкой 404.
3. Если репозиторий всё-таки удаляется: GitHub хранит удалённые репозитории 90 дней, в течение которых их можно восстановить (`Settings → Deleted repositories` у владельца). Удаление необратимо после этого срока — поэтому п. 1 обязателен.

## Важно про актуальность

Архив — исторический контекст, а не инструкция. Требования меняются: в 2022 году был Windows Server 2019 и ADCS, в 2024–2025 — ALT Linux и Samba AD, в 2026 изменились порты, VLAN и состав сервисов. Перед экзаменом сверяйтесь с [`docs/01-normative`](../docs/01-normative/README.md).
